## Classification and score

- Classification: real public Obsidian community plugin; not a conventional app-store package.
- Score: 76/100.
- Confidence: high.
- Current status: version 5.8.11 plugin with deterministic Markdown transformations, AI-assisted correction/summaries/tags/frontmatter/filenames/folder classification, previews, restore, OpenRouter configuration, account/character billing, docs, and GitHub release-attestation workflow.

- Branch: `main`; clean worktree; 25 commits; latest observed commit `f8b6e8c` on 2026-09-21.
- Meaningful LOC: approximately 3,640 across 13 tracked production JS/TS/CSS files. Method: production source/UI only; excludes docs, tests, generated/dependency/build/media content.
- Evidence: `manifest.json`, `src/`, `main.js`, `styles.css`, `README.md`, `docs/USER_GUIDE.md`, `docs/TRANSFORMATIONS.md`, and `.github/workflows/release-attestations.yml`.

## Findings

- The plugin has a broad, coherent workflow and explicitly previews writes, rejects stale previews, and supports restore. Privacy documentation correctly states that selected note content is sent to the configured AI provider and that the plugin has no telemetry/ads.
- No automated test suite is tracked. Transformation correctness, frontmatter/code-block/link preservation, folder preview/apply, stale-preview refusal, restore, provider errors/timeouts, and billing pending-event replay need regression coverage.
- README calls this checkout a private/source mirror and describes copying a `publish/` tree to a separate public repository, while the assigned checkout itself is named/public-looking and no tracked `publish/` directory was observed. Make the canonical source/public release workflow unambiguous and enforce it in CI.
- The optional built-in encrypted fallback/provider-key design is still client-side obfuscation, not a perfect secret boundary. Use spend-limited credentials and keep provider/key disclosure current.

## Distribution readiness

- Package: validate clean build output, source/bundle/manifest version parity, attested GitHub release assets, Obsidian minimum version, and upgrade behavior.
- Listing: provide screenshots/GIFs for preview, transformation categories, restore, settings/privacy, and billing; keep network/content disclosure and support links public.
- Age rating: not applicable to a conventional store; community-plugin policy and AI/privacy disclosure apply.
- Monetization: character-based one-time packs and server-authoritative free usage need clear cost, account, offline, refund, retry, and content-privacy semantics.

## Priority actions

1. Add transformation, preview/restore, provider-failure, and billing integration tests.
2. Reconcile private-source/public-release directory conventions and enforce clean-package CI.
3. Re-audit key fallback, provider payloads, and billing event retry behavior before the next release.
